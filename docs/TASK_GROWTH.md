# 集中タスクとジョブチェンジ

集中画面下部の「タスクを入力してAIで成長配分を決める」から、取り組む内容を手入力します。未設定で「集中を開始」を押した場合も入力画面が開きます。

「AIで配分を決める」を押すと、入力したタスク名をGoogle Gemini APIへ送信します。AIが知識・創造力・継続力・体力・洞察力・共感力への配分と理由を判定します。結果画面には集中時間に応じた獲得予定ポイントを表示します。手動配分・配分プリセットはありません。過去のタスクを選んだ場合も文章を再判定できます。

合計は集中成功1分につき10ptで固定し、AIは合計10枠を分野別に振り分けます。タスクの文面で大量のポイントを要求しても総量は増えません。例えば知識6・継続力2・洞察力2と判定された場合、30分成功で知識180pt・継続力60pt・洞察力60ptです。失敗・中断では獲得しません。

AIの配分・理由・モデル・判定基準のバージョンはタスクと一緒にセッションへ保存します。結果を確認してから「このタスクに設定」を押します。文章を変更すると判定は無効になり、再判定が必要です。通信失敗・不正な応答・曖昧なタスクでは再試行や具体化を促し、固定配分を代わりに使いません。

従来の記録はそのまま読み込めます。AI判定のない過去のタスクは、新しい集中を始める前に判定し直します。過去の集中記録には遡ってポイントを付与しません。

キャラクター画面の「成長・ジョブチェンジ」で累積値と各職業の条件を確認します。2分野の必要値を両方満たすと転職可能です。

転職で成長ポイントは消費しません。名前・性別・レベル・経験値・所持装備を引き継ぎ、戦闘の基礎能力と表示は転職先に切り替わります。称号は転職先のレベル対応の称号に更新します。初期職業と転職済み職業には戻れます。集中中・冒険中・パーティー接続中の転職はできません。

ポイントは戦闘能力と別に保存し、成功時の経験値と同じ保存トランザクションで一度だけ加算します。旧セーブデータは成長0ptから読み込めます。条件は `mobile/lib/features/character/domain/job_progression.dart`、分野と加算規則は `mobile/lib/features/focus/domain/focus_task.dart` で管理します。

## WindowsでGeminiの無料枠を試す

1. [Google AI StudioのAPIキー画面](https://aistudio.google.com/api-keys)でAPIキーを作成します。無料枠で試す場合は、課金を有効にしていないプロジェクトを選びます。
2. Windowsの「環境変数を編集」→「ユーザー環境変数」の「新規」で、変数名を `GEMINI_API_KEY`、値を作成したキーに設定します。キーはチャット・ソースコードに貼り付けないでください。
3. 新しい環境変数が反映される状態でFocusQuestを起動し直します。反映されない場合はWindowsへサインインし直してください。
4. 集中画面でタスクを手入力し、「AIで配分を決める」を押します。分野別のポイントと理由を確認して「このタスクに設定」を押します。

初期モデルは無料枠のある `gemini-3.5-flash-lite` です。無料枠には回数・トークン数などの制限があり、実際の上限は[Google AI Studio](https://aistudio.google.com/)で確認してください。無料枠で送信した内容はGoogleの製品改善に利用される条件があります。詳しくは[公式料金表](https://ai.google.dev/gemini-api/docs/pricing)と[利用制限](https://ai.google.dev/gemini-api/docs/rate-limits)を参照してください。

利用上限で停止し、有料モデルや別サービスへ自動で切り替えません。ただし、課金済みプロジェクトのAPIキーを使用した場合の費用をアプリが無料にすることはできません。無料で試す際はプロジェクトがFree Tierであることを確認してください。

Windowsアプリと同じフォルダーの `focusquest_task_ai.exe` がアプリ起動時に非表示で起動します。キーはこのゲートウェイが環境変数から読み込み、配布ファイルには含めません。サーバー側の `TASK_AI_MODEL` 環境変数でモデルを変更できますが、無料対象かどうかを料金表で確認する必要があります。

ローカルゲートウェイは `127.0.0.1:8787` だけで待ち受けます。タスク名以外のプロフィール・レベル・集中履歴をAIへ送りません。Geminiの構造化出力を使用し、返却された値をサーバーとアプリの両方で検証します。同じタスクの成功した判定結果はゲートウェイが動作している間に限り最大128件までメモリに保持し、API呼び出しを節約します。起動し直すとこの一時保存は消えます。

Geminiへの切り替え前に保存したOpenAIの判定済みタスクも読み込めます。手動配分だけの古いタスクは、新たに使用する前にAI判定が必要です。

開発時は `scripts/start-task-ai-server.ps1 -Foreground` で起動できます。AndroidにはPCのループバックアドレスで接続できません。Android向けのHTTPSゲートウェイと認証は別途用意し、`TASK_AI_URL` をビルド設定で指定する必要があります。このローカルゲートウェイをそのままインターネットへ公開しないでください。

検証：`flutter test --no-pub test/task_ai_http_test.dart test/task_ai_test.dart test/task_job_progression_test.dart`。HTTPテストは模擬のGeminiエンドポイントを使い、実APIの課金を伴いません。実際のモデルによる配分の適切さは、APIキー設定後に実タスクで確認してください。仕様は[Gemini公式の構造化出力](https://ai.google.dev/gemini-api/docs/generate-content/structured-output)を参照。
