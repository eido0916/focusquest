# オンライン集中パーティー

「集中する」→「パーティを組む」→「パーティーを作成」。リーダーが6文字のコードをコピーしてフレンドに伝え、フレンドは「コードで参加」を選ぶ。別々のWi-Fi・モバイル回線でも、同じ公開サーバーに接続していれば参加できる。1人の待機室を作成でき、共同集中は2〜4人で開始する。

リーダーが15/30/45/60分を選択し、全員が「準備OK」を押してから「みんなで集中を開始」。時間を変更すると全員の準備を解除する。サーバーで参加人数・リーダー・準備状態を検証し、3秒後の共通開始日時とセッションIDを配信する。開始を受け取ると各端末で保存し、集中画面から共同戦闘へ進む。

左側に各メンバー、右側に人数分の敵を配置。敵は6秒ごとに人数分のwaveとして出現し、4waveごとにスキルを表示する。原画v010を128×128のまま、JSONの保持tickで切り替える。変形・補間・フェードは使わない。移動と消滅の座標は原画JSONのroot_offset_pxで処理。原素材は上書きしない。9職業・男女18体を使用し、原画が未制作の7職業は既存職業の原画へ対応付ける（職業・名前・レベルは待機室で表示する）。ソロの戦闘には変更を加えない。

報酬は各端末の従来の集中処理で判定し、人数では増やさない。戦闘の討伐演出は報酬に影響しない。開始時のメンバーと時計差をセッションに保存し、接続切れ・画面オフ・再起動後も集中と共同戦闘表示を復元できる。通信切断・パーティー退出では集中を中断しない。本人が集中を中断すると本人だけ報酬なし。待機中のリーダー退出では次の参加者へリーダーを移す。集中中の新規参加を拒否する。集中開始前に権限を確認し、保存や権限確認に失敗した端末には開始失敗を表示する。

2026-10-12: 戦闘画面を参照画像の濃紺・金枠デザインへ更新。左のカードは以前制作した男女16職のドット絵顔画像・職業紋章・名前・レベルを表示し、HP・MPバーは設けない。戦場の仲間は左側の2列、敵は右側へ配置する。背景は一人用の集中と共通で、章に応じて草原・幽霊船に切り替わる。原画切替・集中時間・オンライン同期は維持する。個別の金枠素材と実画面プレビューは [パーティ集中画面 v001](../art/party_focus_v001/README.md) に保存。

## サーバー公開と接続先

2026-10-11にRenderの無料サービスを公開。標準の接続先は `wss://focusquest-party.onrender.com/party`。接続先を手入力せず、パーティーコードで参加できる。ヘルスチェックと公開WSS経由の4クライアント参加・5人目拒否・準備確認・共通開始時刻を検証済み。

初期動作確認向けにRenderの無料枠用 `render.yaml` を追加。アカウント登録から公開URLの取得までは [Render公開手順](../server/DEPLOY.md) を参照。休止からの起動を待てるよう、アプリの接続待ちは90秒に設定する。

1. Dart SDKのある環境で `dart run server/party_server.dart` を実行（PORT環境変数、既定8080）。または `docker build -t focusquest-party server` と `docker run -p 8080:8080 focusquest-party`。
2. WebSocket対応の公開ホスティングまたはTLSリバースプロキシから `/party` を公開し、`wss://公開ホスト/party` を用意する。`/health` はヘルスチェック。HTTPの待機タイムアウトを集中時間以上に設定する。
3. 接続先を変更する場合、APKビルド時に `--dart-define=PARTY_SERVER_URL=wss://公開ホスト/party` を指定する。このPCでは `./scripts/build-android.ps1 -PartyServerUrl 'wss://公開ホスト/party'`。指定しなければ標準の公開サーバーを使用する。ユーザーはコード入力だけで参加できる。待機室に接続先入力欄は設けず、集中時間を設定する。アプリはWSS接続のみ許可する。

ルームは単一サーバープロセスのメモリ内に保持する。自動スケールを無効にして1インスタンスで運用する。サーバー再起動・全員の接続断で待機室が消えるが、開始済み集中は端末で続く。切断時はコード再入力で待機室へ再参加する（集中中への途中参加・自動再接続は未対応）。初期実装はコード参加であり、フレンド一覧やアカウント認証は含めない。パーティーには表示名・職業・性別・レベルと集中状態だけを送信し、対象アプリ・使用履歴・端末内ゲーム記録は送信しない。

## 検証

`flutter analyze --no-pub`、`flutter test --no-pub test/party_online_test.dart test/party_ui_test.dart`。実WebSocketによる4クライアントの参加・5人目拒否・未準備拒否・リーダー以外の開始拒否・時間変更時の準備解除・共通開始時刻・途中参加拒否・切断時の固定メンバー・リーダー引継ぎ・各端末保存・旧保存互換・中断時の報酬重複防止を確認する。

公開サーバー経由の別回線・Android画面オフ時の接続維持は、公開先設定後に実機で確認する。Androidがバックグラウンド通信を切断することがあるため、オンライン表示の継続を集中達成の条件にはしない。

2026-10-11検証結果：静的解析は問題なし。パーティー通信5件・待機室と戦闘表示3件・女性版の既存集中／冒険6件の計14件が合格。原画577枚のファイル一致・RGBA SHA256一致・128×128寸法を確認。2人／4人の画面は `output/party/party-2.png` と `party-4.png` に保存。全体テストでは既存の拳闘士アニメーションの時間比較に不一致（拳闘士1.01秒・剣士0.995秒）が残っている。このパーティー変更では既存のソロアニメーション時間を変更していない。
