## 3. 素材の共通仕様

### 3.1 解像度・描き込み量

| 項目 | 採用する制作基準／仮決定値 |
|---|---|
| 制作用キャンバス | 主人公1フレーム1024×1024px。パーツ分け、リグ、補間を保持する |
| 戦闘用書き出し | 256×256px固定、24fps。全状態・男女とも同一寸法 |
| ホーム用静止画像 | idleの基準ポーズから512×512pxを書き出す。256版と同じ構図・正規化アンカー |
| 主人公の基準身長 | 頭頂から接地まで約192px（256版）。男女とも同じ基準身長。髪飾りなどは別扱い |
| 基準ポーズの頭頂／足元 | 頭頂y≈32、接地y=224。基準立ち姿をA0と呼ぶ |
| 戦闘の表示寸法 | 既存どおり、フレーム全体72×72論理pxを初期試作値とする |
| ホームの表示寸法 | フレーム全体150×150論理pxを初期試作値とする。既存のsize150とAlignを利用し、後工程でウィジェットの幅を正方形に対応させる |
| 非戦闘の冒険表示 | フレーム全体160×160論理pxを初期試作値とする |

256版を72で表示すると基準身長は192×72/256=54論理pxとなり、現行戦闘Placeholderの高さ54と一致する。これが256px採用の根拠。ホーム150では基準身長112.5論理pxとなり、現在の図形の頭頂から靴底まで約121論理pxに近いが、最終の見た目は実機で判定する。

ホームの現行112.5×150枠に正方形PNGをcontainすると全体112.5×112.5、身長約84.4になり、小さく見える。そのため枠の正方形対応は表示確認時の必要作業として明示する。幅112.5、高さ150へ別々に伸ばして合わせない。

ホーム150論理px・DPR3の例では画像に約450物理px必要なので、静止画像は512版を用いる。戦闘72・DPR3なら216物理pxで256版に収まる。実機のDPRは未確認。ホームもアニメーションさせる場合、256版の拡大を自動採用せず、512連番の必要性と負荷を再判定する。現時点ではホーム静止、戦闘アニメーションを試作の前提とする。

### 3.2 透過・向き・アンカー

- RGBAの透過PNG、sRGB、8bit/チャンネル。白・黒の背景を焼き込まない。半透明の縁とエフェクトを維持し、白いマット縁を残さない。影は今回の主人公画像に含めない。
- 主人公は**右向きの横向き寄りの斜め姿**。敵は画面右側なので右向きが自然。顔の両目を正面に並べる正面姿で統一しない。
- 左向きは足元アンカーを軸とする左右反転で対応可能な意匠とする。文字、片方向に意味を持つ紋章などを入れない。利き手・装備の左右も反転することを許容する。現行コードに反転処理はない。利き手の厳密維持が必要になった場合は別制作として再合意する。
- 画像座標は左上(0,0)、右へ+x、下へ+y。**足元アンカーP=(128,224)**、正規化(0.5,0.875)。制作元では(512,896)、512版では(256,448)。Pは地面上のキャラクター基準点で、毎フレームの足の重心を測って移動させない。
- 表示時は`画像左上 = 地面基準点 − P × 表示倍率`。ただし現行戦闘描画は中心指定なので、72表示で地面基準点は`center+(0,27)`になる。この関係を利用して試作し、素材側で原点をずらさない。
- 現行の基準center=(W×0.25,H×0.5)から求める足元はy=H×0.5+27。一方、背景の地面開始はH×0.66で、両者は常に一致しない。素材だけで接地を保証できない。後工程で既存の_actor内の配置を局所調整する必要性を実機で判定する。
- 走行はその場走り。Pやカメラを右へ流さない。上下の体重移動・手足の動きは許容するが、接地足は地面y=224を踏む。跳躍では足が離れてよいが地面基準Pは固定する。

### 3.3 表示範囲・全フレーム共通条件

- 人物、剣、髪、衣服は全動作で原則x=16〜240、y=16〜240内。画面端までの最低16pxの透明余白を残す。A0の頭頂y≈32、足元y=224を基準にする。
- これは剣・髪を含む動作全体の安全範囲。髪の長い女性だけ小さく縮める、攻撃時だけフレームを広げる、剣先だけ切る処理は禁止。収まらない場合は剣の振り方・リグを試作段階で調整する。
- 固定する項目：キャンバス寸法、P、基準身長、向き、カメラ位置・倍率、パーツ比率、衣装、剣の長さ、フレーム番号・時間定義、書き出し設定。トリミング・フレームごとの自動中央揃え・自動フィットは禁止。
- 一連の動作の中でしゃがむ・跳ぶことは体の変形として表現する。見える外接矩形の変化を理由に表示倍率を変えない。
- 男女で骨格の基準点、足元、剣の接触位置、タイムラインを共通化。体格・髪・服装の違いは同じ身長基準内で表現する。足運びや胸・腰の形を完全に同じ絵にする必要はない。
- アニメーションの体の上下動を採用する場合、現行idleの±3pxの上下移動は後工程で重ねないよう調整する。攻撃の前進24pxはシステム側の移動とし、画像の中で同じ移動を加えない。

### 3.4 縮小・ぼやけ防止

- 元データから最終寸法へ一度で縮小。面積平均または高品質バイキュービックを基準とし、実際に使った方式をメタデータへ記録する。半透明境界を保ち、縁の黒ずみ／白い縁／過度なシャープ処理を避ける。
- 1024→256、1024→512を別々に生成し、256から512を拡大して作らない。全フレームに同じ縮小設定を使用する。
- 72論理pxの戦闘表示で読める顔、剣、輪郭を優先する。256版の主要輪郭は約4px以上を出発点とし、細い線や1pxの装飾に意味を依存させない。
- 現行戦闘のPaintにはfilterQualityの指定がない。将来の表示試作で、なめらかな絵に適したフィルタを局所設定し、にじみとギザギザを実機で比較する。設定変更済みとは扱わない。
- 画像の縮小とアプリの拡縮は別工程。アプリでは同じ正方形の表示倍率を保つ。静止画像の配置は可能な範囲で物理ピクセル境界に合わせ、アニメーションの移動まで不自然に丸めない。

### 4.1 動作を切り替える条件

- 全動作のP・倍率・フレーム寸法は共通。前の動作の外接矩形を使って次の画像を中央揃えしない。
- run→run_slash→runはR0を共有して接続。初期試作はループ境界で切替え、任意の走行位相で接続する素材までは量産しない。
- idle↔run、run→skill / ultimateは異なる基準姿勢なので、制作元に4フレーム（約0.167秒）の短い接続を試作できる余地を残す。これは表の各クリップの時間に含めず、戦闘演出の開始遅延に含めるかはシステム担当が決める。足元やサイズの変更で接続をごまかさない。
- ホームの次動作はidle、戦闘の非攻撃時も現行はidle。走行を戦闘の通常状態にするかは未確定。走行を背景移動と結びつける実装を今回の前提にしない。

### 4.2 現行攻撃タイミングとの不整合と量産保留

現行コードは、HP減少→DamageEvent発行→攻撃画像表示の順。0.75秒のrun_slashをイベント受信時にF0から再生すると、HPが減ってから約0.333秒後に剣が当たる。攻撃表示自体も0.3秒で終わるので、**上表はそのままの差替えでは成立しない**。

既存のBattleEngine、FocusBattleGame、AssetCatalogを活用し、後工程でこの描画境界に再生とイベント同期を局所追加する。別エンジンや別アニメーション技術への移行は行わない。まず次を決めてから攻撃クリップを確定する。

1. HP減少・ダメージ数字・被弾・剣の接触を同じ命中時点に揃える方法。予備動作の開始を現行攻撃周期のどこに置くか、初回攻撃・致死打・同時攻撃も含めて確認する。HP減少を動画に合わせて勝手に二度適用しない。
2. speed上昇で0.75秒より短い間隔になったときの扱い。候補は再生時間の短縮（男女共通倍率で命中時点も換算）で、適用倍率と読みやすさは未確定。命中イベントを落とす、勝手に攻撃間隔を伸ばす仕様にはしない。
3. 単発動作の中断・再開。死亡は優先し、被弾で毎回attackを最初から再生し直さない方針とする。細かい割込み優先順位は要検証。
4. 致死打後の長い技の回収と、現在の0.6秒後の戦闘完了通知の整合。見た目の完了待ちと報酬保存の一回性を確認する。
5. skill / ultimateの発動条件とゲーム効果。まだ存在しないので、試作は明示的な演出プレビューで評価する。通常戦闘で使えると記載しない。

現行の0.3秒表示を変更できない条件が後工程でも続く場合、代替案は**7フレーム／約0.292秒、F0命中の短い斬撃**。予備動作を含む0.75秒版と同じ表現にはならないため、採用する場合は仕様を改訂してから作る。18フレームを0.3秒へ押し込む60fps再生を24fps納品として扱わない。

## 5. 主人公・武器・エフェクトの分け方

| 対象 | 制作元 | 実装用の納品単位 |
|---|---|---|
| 人物の体、髪、衣装 | パーツ・リグを分けて保持 | 1フレームに合成。アプリ側で手足のパーツを動かす前提にしない |
| 剣 | 独立レイヤー、握り位置と前後関係を保持 | **人物と合成**。前面／背面の入替えも制作側で完成させる。装備に応じた剣の外観差替えは現在の対象外 |
| 通常斬撃の光・軌跡 | 人物と別レイヤー | **共有FXの透過連番**。初期キャンバス256×256、P=(128,224)、主人公と同倍率・同タイムライン |
| スキル・必殺技の光、魔法陣、大きい斬撃 | 人物と別レイヤー | **別FXの透過連番**。初期キャンバス512×512、P=(256,384)。主人公の256版と同じpx当たりの世界倍率で描く |
| 命中の閃光 | 独立レイヤー | 必要なら敵の接触点基準で別FX化。位置、サイズ、使用有無は攻撃試作時に決める |
| 接地影、ダメージ数字、HPバー | 主人公に焼き込まない | 既存UI／描画の担当。影追加の要否は後工程 |

大きいFXを主人公256の中へ詰めない。FXのために人物を縮小したり、動作ごとに人物キャンバスの寸法を変えたりしない。512のFXを主人公と同じ72×72へ描くこともしない。

倍率s=72/256の例では、512FX全体は144×144論理px。主人公のPとFXのPを同じ地面基準点に合わせる。これにより中心位置の違うキャンバスでも整合する。仮のFX枠を超える演出は試作段階で相談し、画面全体に覆いかぶさる演出は現仕様に含めない。

FXは主人公と同じFPS・フレーム数で出力し、発動前・終了後は透明フレームを含める。run_slashのFXはF8から、skillはF12から、ultimateはF24からを仮基準とし、主人公クリップ終了までに消す。前面FX／背面FXが必要なら`_front` / `_back`に分け、描画順をメタデータに書く。

男女で共有するものは動作設計、骨格基準、時間、命中フレーム、同じ剣の元パーツ、FX。人物の画像は男女別。衣装による微調整を行っても共有FXの発生点はずらさない。職業4種への外観展開は今回の男女2種と別の話なので量産範囲に自動追加しない。

## 6. 納品仕様

### 6.1 正式受け渡しは透過PNG連番

**PNG連番を正本とする。** 1枚ずつ寸法・足元・透過を検査でき、仮素材を既存の単独画像差替え口へ渡せる。アニメーション方式の決着前にシートの巨大画像を作り込まずに済み、フレームや時間の修正も容易。

連番でも現行実装は自動再生しない。システム担当が後工程で既存Flame描画に再生を追加する。読込み単位、メモリ、速度の実機確認後、必要なら連番から実装用シートを機械生成する。シート化自体でデコード後のメモリ量が小さくなるとは限らない。

### 6.2 シートを生成する場合の共通ルール

- 4列、最大4行、1ページ16フレーム。左→右、上→下の行優先。ページ番号は0始まり。
- 256版：セル256×256、セル間余白0px、外周余白0px、トリミングなし。画像は1024×1024。フレーム内の最低16px透明余白が隣セル混入の防止余地になる。余白へ色をはみ出させない。
- 512FX版：セル512×512、4×4で2048×2048。他の規則は同じ。シートのsrc矩形外をサンプリングして縁が出ないことを実機で確認する。
- 最後のページの未使用セルは完全透明。透明セルを再生フレームとして数えない。
- idle / run各2ページ（16+8）、run_slash2ページ（16+2）、skill3ページ（16+16+4）、ultimate4ページ（16+16+16+12）。
- Fのページはfloor(F/16)、その中の列は(F mod 16) mod 4、行はfloor((F mod 16)/4)。アニメーションはページ境界でも連続する。
- 可変サイズアトラスや自動回転パックは採用しない。受け渡し時にフレームの原点が失われるため。

### 6.4 再生メタデータ

### 6.5 確認動画・制作元

- 動画はMP4/H.264、固定24fps。チェック柄、暗い森色、明るい単色背景の各表示を含める。動画は透過の正本ではない。透過品質はPNGで確認する。

- source / previewは納品保管用。APKのassetsには含めない。承認済み版は上書きせず、版番号と変更履歴を残す。
